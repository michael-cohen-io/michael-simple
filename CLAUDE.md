# michaelcohen.io

One-page personal site (plus a 404 page): Next.js 16 (App Router, Turbopack, static export to `out/`, React Compiler and typed routes on), React 19.3, Tailwind CSS 4, a few shadcn/ui primitives on Base UI (`@base-ui/react`; parts take `render`, not `asChild`), Raleway via `next/font`, no icon library (glyphs are inline SVGs). Deployed on Vercel as static files (framework preset "Other", `outputDirectory: out`) behind one Routing Middleware, `middleware.ts`.

## Rules

- Package manager is **bun** only. Never npm, pnpm or yarn; never edit `bun.lock` by hand.
- `api/ask.ts` is the one Vercel Function (Node, Web `Request`/`Response`; `package.json` has `"type": "module"` because Vercel emits the function as ES-module JavaScript and Node would otherwise load it as CommonJS and crash on the first `import`; its relative imports name `.js` files, `../src/lib/ask.js`, because Node's ES-module resolution wants exact file names and Vercel compiles each traced `.ts` to that name): it answers the "Ask Claude about me" box (`src/components/ask/ask.tsx`) from `public/index.md` (bundled with the function via `functions.includeFiles` in `vercel.json`), through a Claude Managed Agent when `ASK_AGENT_ID` and `ASK_ENVIRONMENT_ID` are set (provision once with `bun scripts/ask-setup.ts`, publish a prompt, tool or link change with `bun scripts/ask-setup.ts update`; the model and prompt are `src/lib/ask.ts`, shared by both paths; the agent's tools are web search and web fetch, allowed the domains the page links to, which the script derives from the content files and also sets as the environment's egress list, plus one custom tool, `restyle_page` (Party Mode): its catalog, validator and merge are `src/lib/party.ts`, the function answers the tool call itself and returns `effects` with the answer, `src/components/party/party.tsx` applies them to `<html>` and the page's text nodes and the CSS lives at the end of `globals.css`, all behind `data-party-*` attributes, so the agent never writes CSS, selectors or markup; every pink token in `globals.css` derives from `--pink-hue` (the accent as a `calc` offset), which is how one hue recolours the page; the browser sends the page's text runs with each question and the tool's `list_text` step returns them, so a translation covers every run; the function has 120 s (`vercel.json`)because a full rewrite is one long tool call; session ids are `sesn_…`, the turn ends on idle with a stop reason other than `requires_action`, and a session that hit its budget is not reused) and otherwise one Claude API call. The answer is a `text/event-stream` (`delta`, `message`, `tool`, `effects`, `done`, `error`; the generators are `src/lib/ask-stream.ts`, the SSE framing in `api/ask.ts`, the parser in `ask.tsx`), and `tests/ask.spec.ts` drives the agent loop with a scripted fake session (tool calls, a bad call, `list_text`, budget, termination, errors): extend those tests when the loop changes. It needs `ANTHROPIC_API_KEY` in the Vercel project; without it the box reports "not set up". Request errors are RFC 9457 problem documents before the stream starts, and an `error` event after; the in-memory rate limit is per instance, so add a Vercel Firewall rule on `/api/ask` for a durable one. The middleware passes `FUNCTION_PATHS` through; `tests/ask.spec.ts` calls the handler without a network and the smoke test mocks the route.
- Content lives in `src/content/` (`work.ts`, typed by `types.ts`, bullets one line of Markdown each; `writing.ts` for the Writing & Talks section under the work history; `resume.ts` for the PDF's contact line, education and skills). There is no database: no Postgres, no Prisma, no env vars needed to build.
- `public/index.md` and `public/llms.txt` are one and the same document (the llms.txt shape, then the whole page as Markdown; `/` serves it when a request prefers `text/markdown`, by the rewrite in `middleware.ts`), `public/resume.json` (the JSON Resume document) and `public/openapi.json` (an OpenAPI 3.1 description of those files, the PDF and the sitemap; there is no other API) are generated by `scripts/build-llms.tsx` from the same content files, before every `dev` and `build` (`bun run generate`), and are never committed.
- The resume PDF (`public/MichaelCohenResume.pdf`) is generated, never committed: `scripts/build-resume.tsx` renders `src/resume/document.tsx` (react-pdf, Raleway bundled in `src/resume/fonts/`) from `src/content/work.ts` and `src/content/resume.ts` before every `dev` and `build` (`predev`/`prebuild`). Curate the one-pager with the `resume` fields in `work.ts` (shorter bullets, fold a company, or leave a role off); the build fails if it exceeds one page.
- Response headers and the `*.vercel.app` redirect are in `vercel.json`, not `next.config.mjs` (a static export ignores `headers()`/`redirects()`). `vercel.json` rewrites run after the filesystem, so they never fire for a path that is a file; use the middleware for that.
- `middleware.ts` at the root is Vercel Routing Middleware (`@vercel/functions`), not Next middleware: it rewrites `/` to `/index.md` for clients that prefer Markdown and answers unknown paths with a negotiated 404 (Markdown, an RFC 9457 problem document for JSON clients and by default under `/api`, `/v1` and `/graphql`, or a pass-through to `404.html` for browsers) and logs one JSON line per miss to the Vercel runtime logs. `next build` compiles it too and warns that a static export ignores middleware; that warning is expected. Its `KNOWN_PATHS` set must list every path the export publishes: `scripts/check-paths.ts` (postbuild) compares it with `out/` and fails the build on any difference, so adding a file to `public/` or a metadata route means adding it there. `tests/middleware.spec.ts` calls the middleware directly.
- Every metadata route (`manifest.ts`, `robots.ts`, `sitemap.ts`, `opengraph-image.tsx`) exports `dynamic = "force-static"`; without it the static export refuses the route. Declare it in the file that owns the route (Turbopack reads segment config statically, so `twitter-image.tsx` cannot re-export it from `opengraph-image.tsx`).
- Tailwind is configured in CSS, not JavaScript: `src/app/globals.css` imports `tailwindcss`, binds `dark:` to next-themes' class, and maps the OKLCH palette (`--primary` once per theme, every surface a lightness stop of `--pink-hue`, on `:root`/`.dark`, which also set `color-scheme`) to colour utilities through `@theme inline`. There is no `tailwind.config.ts`; add tokens to the `@theme inline` block. The smoke test checks the accent's contrast on both grounds.
- Keep the site's identity: one pink accent, Raleway, the lowercase `<mc>` mark, the timeline. Refine, don't redesign.
- UI follows Vercel's Web Interface Guidelines (`vercel-labs/web-interface-guidelines`, `command.md`): every interactive element has a `focus-visible` ring and a hover state, icon buttons an `aria-label`, decorative SVGs `aria-hidden`; headings, buttons and the skip link are Title Case, copy uses curly apostrophes, `…` and numerals; dates go through `Intl.DateTimeFormat` pinned to UTC (`src/lib/work.ts`); brand names, handles and code carry `translate="no"`; `html` has `scroll-padding-top` and every `[id]` a `scroll-margin-top` for the sticky bar; links and buttons set `touch-action: manipulation` and a themed tap highlight; animations touch only `transform`, `translate`, `opacity` and `filter`; the agent view is in the URL (`?view=agent`, `src/lib/view-store.ts`); Party Mode always shows a fixed "Turn It Off" control and stops on Escape. Re-audit against the file when adding UI.
- The work history is one component, `src/components/work/WorkHistory.tsx`: a timeline whose rows are Base UI accordion items at every width (first company open, any number open), with a container query (`@2xl:`) moving the date into its own column. Closed panels stay mounted (`keepMounted`) so the whole history prints. Motion is CSS and sparse: the spine draws on the dot's view timeline (`.timeline-*` in `globals.css`) and the panel opens on Base UI's `data-starting-style` frame; the theme switch is instant; everything sits behind `prefers-reduced-motion`. Cards are flat (a tint of the accent and a hairline border, no shadow) in both themes.
- The header is a sticky bar (the `<mc>` mark and the two switches) with the portrait and name in normal flow under it. The human | agent switch (`src/components/agent/`) swaps the page for `/llms.txt`, fetched on first flip, with a copy button for the curl line; `data-view="agent"` on `<html>` hides `.human-view`.
- Before opening a PR run `bun run typecheck && bun run lint && bun run build && bun run test:e2e`; `lint` is `eslint .` (ESLint 9 with the native flat presets of `eslint-config-next` 16 in `eslint.config.mjs`; `next lint` is gone in Next 16), and the build must produce `out/index.html` and fails on a malformed or empty work history. The smoke test (`tests/smoke.spec.ts`, Playwright, Chromium only) serves `out/` itself, so it never runs the middleware (`tests/middleware.spec.ts` covers that); CI (`.github/workflows/ci.yml`) runs the same four commands on every PR.
- ESLint stays on 9. `eslint-config-next` 16.3 declares `eslint >=9`, but its `eslint-plugin-react` crashes under ESLint 10 (`react/display-name: contextOrFilename.getFilename is not a function`); retry the bump when `eslint-config-next` updates that plugin.
- Serve a build locally with any static server, e.g. `python3 -m http.server 3000 --directory out`. The Vercel scripts (`Analytics`, `SpeedInsights`, the error beacon's `track`) only load on Vercel hosts (`isVercelHost` in `src/lib/site.ts`), so a local build makes no `/_vercel/` requests.
